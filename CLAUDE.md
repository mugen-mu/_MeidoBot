# DiscordBot: личный Discord-бот (напоминалки, повторяющиеся дела, порядок в заметках)

Личный хобби-проект Ihor. **Отдельный репозиторий `D:\_MeidoBot` (приватный GitHub `mugen-mu/_MeidoBot`), не часть `D:\_Automation`** (вынесен 2026-11-15 с историей коммитов; раньше лежал в `_Automation/DiscordBot` по его слову 2026-11-07). Рабочее (BES) сюда не кладём, личное отсюда в рабочие репозитории не уходит. Правила — этот файл; корневые правила `_Automation` и его хуки сюда не действуют. Здесь только то, что специфично для бота и общие правила работы ниже.

## Статус
Проектирование закрыто 2026-11-07: пользователь ответил на все 23 вопроса (`docs/DECISIONS.md`). Этап 1 (ядро) и этап 2 (установка: `setup.cmd`, README по кликам) написаны и проверены локально 2026-11-07; дальше первый запуск на живом боте по `README.md` и `LIVE-CHECKS.md` (нужен пользователь, ~15 минут). Код: TypeScript в `src/`, тесты `npm test`, проверка типов `npm run typecheck`. Что и зачем — `docs/DESIGN.md` (раздел 0 «Поправки после ответов» главнее остального текста); исходное ТЗ из чата — `docs/BRIEF-original.md` (не править, это эталон слов пользователя). Исходники страницы решений — `design/`.

## Главное, что нельзя потерять
- **Напоминание не исчезает, пока пользователь не нажал «Готово».** «Отложить» не закрывает дело. Исключение (решение владельца 2026-11-10, прямой ответ в хабе `/sweep`): дело, на разбор которого нет ответа 30 дней, замораживается само — остаётся в базе, не напоминает, не удаляется, возвращается из «Ещё» → «Заморожено» кнопкой «Вернуть»; за 3 дня до заморозки в субботнем разборе есть предупреждение. Повторяющееся дело: каждое повторение — отдельная запись, пропущенное не стирается.
- Бесплатно; Cloudflare Workers + D1; Discord по HTTP Interactions; всё работает без включённого ПК.
- **Адрес бота — личка** (решение 2026-11-11, отменяет A1 от 2026-11-07): кнопка «Личка» в `/settings` → «⋯ Ещё» переносит напоминания, сводки и ввод в личные сообщения (`dmAllOn` в `settings.ts`, `dm_backup` в мете); выключение возвращает каналы сервера. Сервер с ботом остаётся.
- **Панели «Горит» нет** (решение 2026-11-11): про дела спрашивают текстом («что у меня горит», «какие дела», «что на сегодня», «что на неделю» — `src/tasksAsk.ts`, без модели, кнопка «Это было дело»). Новые формулировки — в `FILLER`/ключи `tasksAsk.ts` с тестом; ответ языковой моделью на любую фразу — только по его «да».
- Календарь Google и другие чужие сервисы не подключаем (решение пользователя 2026-11-07): всё внутри Discord.
- Ничего из «идей» не внедрять без его «да»: сначала предложить простыми словами, дождаться ответа.

## Правила проекта
- **Личные аккаунты.** Cloudflare и Discord — только личные пользователя. Корпоративные токены, аккаунты, организации не использовать.
- **wrangler проекта — только через `npm run wrangler -- …` / `npm run deploy` / `scripts/lib/runner.ts`:** у бота свой вход в Cloudflare в `.cf-home/` (через `XDG_CONFIG_HOME`, в git не попадает). Общий вход wrangler на ПК — рабочий аккаунт (`b-eng-s.com`), голый `npx wrangler …` из этой папки сделал бы его владельцем бота. `setup.cmd` не принимает рабочую почту. Из рабочего входа не выходить: `wrangler logout` без `.cf-home` сломал бы другие проекты.
- **Секреты** (токен бота, ключ Discord, ключ для Siri) — только `wrangler secret`, `.dev.vars` (в `.gitignore`) и менеджер паролей. Не в git, не в чате, не в журнале. Скрипт установки спрашивает значения у пользователя в консоли.
- **Установка и деплой — одним действием** (`setup.cmd` / `npm run setup`), без ручной правки кода и конфигов. Вход в Cloudflare (`wrangler login`) и создание приложения в Discord Developer Portal делает пользователь по README; выкладку готового и проверенного — агент, с понятным отчётом.
- **Интерфейс бота и документы — по-русски**, простыми словами, без жаргона (пользователь не программист). Идентификаторы — по-английски.
- **Безопасность текста.** Сообщения, похожие на пароль, ключ или номер карты, бот не копирует, не индексирует, не пишет в журнал: в базе только пометка «от чего это» (без значения и его частей). Сообщение сам не удаляет молча: спрашивает «от чего это?», напоминает перенести в Bitwarden и удаляет по кнопке.
- **Правило кнопок (решение 2026-11-08).** Добавил кнопку, команду или раздел настроек — убери другую или спрячь в «Ещё»: на виду пять команд (`/remind`, `/list`, `/week`, `/menu`, `/settings`), под напоминанием три кнопки (Готово, Отложить, Изменить), на главном экране меню — добавить, сегодня, висит. Режим «просто» и голосовые не делаем.
- **Настройки, а не константы.** Тихие часы, режим «я в отъезде», время сводок и настойчивость переключает сам пользователь в `/settings`; значения по умолчанию в коде — только стартовые.
- **Правда в отчётах.** Деплой отсюда не проверить без входа пользователя в Cloudflare: в отчёте всегда «Проверено локально / Не проверено на настоящем Discord и Cloudflare».
- **Коммиты** — префикс `DiscordBot:` (оставлен ради истории), коммитим только своими путями: `git add <пути>`, затем `git commit -m "…" -- <те же пути>` (параллельные сессии в одной папке); `git add -A` / `.` и `commit -a` не используем. Данные пользователя (дела, заметки, дамп базы) в git не кладём. **`git push` — сразу после коммита законченной работы** (`origin` — приватный GitHub `mugen-mu/_MeidoBot`). Историю не переписываем без явной просьбы. Git-хуков здесь нет: перед коммитом смотри свой `git diff --cached`.
- **Язык.** Говорим и пишем по-русски; владелец не программист. Технические развилки решай сама и коротко скажи, что выбрала; спрашивай про то, что увидит человек, и про необратимое — одной фразой, рекомендация первой.
- **«Готово» — только по факту:** собрано и проверено там, где результат должен быть. В отчёте строка «Проверено: … / Не проверено: …». «Проверено человеком» за владельца не пишем. Живые проверки (настоящий Discord, Cloudflare) — в `LIVE-CHECKS.md`: что именно и шаги на 2 минуты; работа их не ждёт.
- **Выкладка (`npm run deploy`) — только по слову владельца** («выкладывай»); без него — не выкладывать.
- **Журналы:** `PROGRESS.md` (новое сверху: Сделано / Проверено / Не проверено / Дальше), `docs/DECISIONS.md`.
- **Не коммитить:** секреты (`.dev.vars`, `.cf-home/`, токены), `node_modules/`, `.wrangler/`, `backups/`, данные `data/` с личным.

## Облачная сессия (телефон, ПК выключен)
- **Признак:** `CLAUDE_CODE_REMOTE=true` (облачная Ubuntu-VM Claude Code). Здесь нет входа в Cloudflare и Discord, `.dev.vars`, `.cf-home/`, секретов, путей `D:\`, личной папки `~/.claude` и git-хуков (их и в этом репозитории нет): префикс `DiscordBot:` и свои пути держи сама.
- **Боевое не трогать:** `npm run deploy`, `wrangler`, `npm run setup`, регистрация команд — только на ПК и по слову владельца. Тесты и типы (`npm ci`, `npm test`, `npm run typecheck`) в облаке запускать можно; в отчёте «Проверено в облаке: тесты / Не проверено: настоящий Discord и Cloudflare».
- **Надиктованное с телефона не обсуждай, а сохрани:** `docs/inbox/ГГГГ-ММ-ДД-meido-<тема>.md` — «Суть» (3 строки), «Сырой текст» дословно, «Проект/репо». Идеи не внедряй (правило выше): только заметка. Коммит в ветку `claude/…`, ответ — одна строка: путь и ветка. Обсуждать — только если написано «обсудим».
- **В `main` не пушить:** только ветка, PR сливает владелец. Данные пользователя (дела, заметки, дамп базы) в git не класть.
- **Другие репозитории владельца** (рабочие и личные): рабочее сюда не кладём, личное отсюда в рабочие не уходит; работая с соседним, сначала прочитай его `CLAUDE.md`.
- **На ПК:** `/inbox` разбирает заметки и ветки `claude/*`. Контекст для чата — `CHAT-CONTEXT.md` и `docs/phone/STATUS.md`: существенно изменил `CLAUDE.md` — обнови `CHAT-CONTEXT.md` в том же коммите.

- `PROGRESS.md` — журнал, новое сверху.
