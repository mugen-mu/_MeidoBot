# Разведка: расписание выхода аниме (этап «Аниме»)

Дата: 2026-11-09. Решения Ihor — `docs/DECISIONS.md`, «2026-11-08 — Ретроспектива», абзац «Аниме (E)»; здесь они не пересматриваются. Кода бота нет, только проба запросов с этого ПК (из Cloudflare не пробовали — это первый шаг реализации, как было с водой).

## Поправка 2026-11-10: проба из Cloudflare

Проба из настоящего Cloudflare (`wrangler dev --remote`, дата-центр WAW, пробный Worker без привязок, живая база не тронута): **AniList отвечает 403 «You have been manually blocked» на любой `User-Agent`** — адреса Cloudflare Workers у него в блоке. Поэтому AniList в бота не берём. **Shikimori отвечает** (поиск, `/api/animes/{id}`, `/api/calendar`: 200 за ~0,1 с) и сам отдаёт время следующей серии (`next_episode_at`) и число вышедших (`episodes_aired`); время у него совпадает с AniList до минуты (пример: 1794189600). Итог: время серий, русские названия и поиск — все от Shikimori; AniList остаётся запасным только для разбора вручную с ПК. Jikan из Cloudflare не пробовали.

## Коротко

- **Основной источник расписания — AniList** (`graphql.anilist.co`): отдаёт точное время выхода каждой серии (секунды UNIX, по Японии как у вещателя), номер серии, id MyAnimeList (`idMal`). Без ключа, быстро (0,4 с), лимит 90 запросов в минуту — нам нужен один запрос в сутки.
- **Русские названия и описание — Shikimori** (`shikimori.io/api/…`; `shikimori.one` перенаправляет на `.io`, адрес уже менялся — держим оба и следуем за перенаправлением). Его календарь (`/api/calendar`, 91 тайтл на неделю, 54 КБ) отдаёт следующую серию и время, русское название — в том же ответе. Номер Shikimori = номер MyAnimeList = `idMal` из AniList, поэтому тайтлы склеиваются без угадывания по названию.
- **Озвучка — AniLibria** (`anilibria.top/api/v1/anime/schedule/week`): 38 тайтлов на неделю (34 идущих), по каждому — день недели выхода озвучки, номер следующей серии, номер последней вышедшей и когда она появилась (`updated_at`), id MAL/Shikimori для склейки. Старый адрес `api.anilibria.tv/v3` закрыт (410) — берём только `v1`. Ответ тяжёлый (317 КБ, внутри ссылки на видео, которые нам не нужны), читаем раз в сутки.
- **Jikan** (`api.jikan.moe`, неофициальная оболочка над MyAnimeList): с этого ПК не ответил (два запроса по 20 с, без ответа). Как основной не берём: лимит 3 запроса в секунду, чужой сервис без договорённостей, нет ничего, чего нет у AniList + Shikimori. Остаётся запасным, если упадёт AniList.

## Что проверили

| Источник | Адрес пробы | Ответ | Что внутри |
|---|---|---|---|
| AniList | `POST https://graphql.anilist.co` (запрос `airingSchedules`) | 200, 0,4 с | `airingAt` (UNIX), `episode`, `media.id`, `media.idMal`, названия romaji/english/native, формат, сезон; поиск `media(search:)` отдаёт `nextAiringEpisode`, `episodes`, `status` (`RELEASING`, `FINISHED`, `NOT_YET_RELEASED`) |

| AniLibria | `GET https://anilibria.top/api/v1/anime/schedule/week` (также зеркало `api.anilibria.app`) | 200, 0,6 с, 317 КБ | `release.name.main` (рус.), `publish_day` (день недели), `is_ongoing`, `next_release_episode_number`, `published_release_episode.ordinal`/`updated_at`, `release.mal.id`, `release.shikimori.id` |
| Jikan | `GET https://api.jikan.moe/v4/…` | нет ответа за 20 с (дважды) | не проверено |

**Сверка времени AniList ↔ Shikimori** (12 тайтлов недели): время серии совпало до минуты почти везде (в двух случаях расхождение в одну минуту из-за округления). Один тайтл (Romelia Senki) показал сдвиг на 2 суток — перенос; такие случаи и ловит правило «расхождение больше часа — предупредить» (E20).

## Что это значит для бота

1. **Склейка по `idMal`.** Тайтл в боте хранится под одним номером (MAL), к нему — id AniList, русское название, оригинал в скобках, постер не нужен. Поиск по названию — через Shikimori (русское) и AniList (оригинальное); неясное — 2–3 кнопки (E31).
2. **Расписание — раз в ночь (E32)** только по «моим» тайтлам: один запрос AniList на пачку id (`Media(id_in: …)`), один Shikimori `/api/calendar` на всех. Запросов в сутки — единицы, лимитов Cloudflare это не касается.
3. **Время хранится в миллисекундах UTC**, показывается по Киеву; «день выхода по Японии» считается из `airingAt` в поясе Токио (UTC+9).
4. **Озвучка.** AniLibria покрывает не всё (38 тайтлов на неделю из ~90 идущих). Для тайтлов, которых там нет, строки про озвучку просто нет. Время озвучки — `updated_at` последней серии (когда появилась), прогноз на будущее — день недели; точного часа в расписании нет.
5. **Сбой источника.** Если AniList не ответил — берём Shikimori; оба молчат — вчерашние данные плюс одна строка «расписание сегодня не обновилось» (как у воды и газа), не чаще раза.
6. **Адреса и условия.** Ключей нет, `User-Agent: MeidoBot/1.0` обязателен для Shikimori. Ссылок на видео и постеров не берём и не храним. Условия AniList: бесплатно для некоммерческого использования; Shikimori просит не больше 5 запросов в секунду и 90 в минуту.

## Не проверено

- Запрос из Cloudflare Worker (первая проверка при реализации: пробный Worker без привязок, `wrangler dev --remote`).
- Как ведут себя источники при переносе и «неделя перерыва» (редкие случаи; проверим при первом сезоне вживую).
