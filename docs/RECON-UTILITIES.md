# Разведка: отключения воды и газа в Днепре (этап 3)

Дата разведки: 2026-11-09 (ночью). Решения Ihor — `docs/DECISIONS.md`, запись «2026-11-08 — Ретроспектива», раздел «Вода и газ (C)»; здесь они не пересматриваются. Кода бота и выкладки нет — только разведка.

## Коротко

- **Вода — источник есть и хороший.** Официальный сайт водоканала `vodokanal.dp.ua` (КП «Дніпроводоканал») — это сайт на WordPress. Новости отдаются готовой машинной лентой (JSON и RSS), без разбора вёрстки. Аварийные и плановые работы там объявляются заранее (за 1–5 дней).
- **Газ — источник есть, но беднее.** Оператор в Днепре — **«Газорозподільні мережі України» (Дніпровська філія)**, сайт `dp.grmu.com.ua`. Раз в месяц он публикует файл `.docx` со списком **домов по датам** (до подъезда). Лент нет: файл находим на главной странице. Срочные аварии по газу компания пишет только **после** события.
- **Главное ограничение воды:** в тексте названы **районы** («Новокодацький, Чечелівський»), а адреса — только на картинке-карте Google. Поэтому «по улице» для воды работает слабо, «по району» — хорошо.
- **Telegram-каналов служб** (запасной вариант) не нашёл: у обеих служб в ссылках только Facebook, а его без входа читать нельзя. Запасного пути нет — если сайт поменяется, бот скажет об этом один раз (как решено).
- **Не проверено главное:** запрос именно из Cloudflare Worker (отсюда доступны с моего ПК, без защиты от ботов, но с Worker не пробовал — выкладывать нельзя). Это первая проверка при реализации (шаг 1 плана).

Образцы живых сообщений (публичные, без личных данных):

- «…з 22:00 години 4.11.2026 до 22:00 години 6.11.2026 буде припинено водопостачання … Новокодацького та Чечелівського району, знижений тиск у Соборному, Центральному та Шевченківському … Відновлення … очікується на 12:00 07.11.2026» (запись 2 ноября).
- «Скасування робіт на правобережжі … заплановані роботи … скасовуються» — **без названия районов** (31 октября).
- «Зміна дати проведення робіт … з 22:00 31 жовтня до 22:00 2 листопада» (30 октября).
- «26 вересня 2026 року з 01:00 до 23:00 … можливе тимчасове відсутнє водопостачання або зниження тиску у: Чечелівському, Центральному, Соборному, Шевченківському районі … Нормалізація тиску очікується до 14:00 27 вересня».

Главные особенности текста (важно для разбора):
1. Формат дат гуляет: «4.11.2026», «31 жовтня», «26 вересня 2026 року з 01:00 до 23:00». Быстрый разбор регулярным выражением поймал диапазон в 3 записях из 5 — значит, **время бот должен считать «неподтверждённым»**, если не разобралось, и показывать выдержку текста как есть.
2. Отмена и перенос — отдельные записи, часто без районов. Их надо трактовать как «обновление предыдущего»: «Скасовано» + ссылка.
3. «Знижений тиск» и «припинено водопостачання» — разные вещи (в одной записи есть и то и другое для разных районов); надо различать и подписывать.
4. Записи иногда правят после публикации — следить по `modified_gmt`, а не только по `id`.

## Пример разбора (работает на сохранённых образцах)

Образцы лежат в `data/recon/` (папка в `.gitignore`, в репозиторий не попадает): `vk_feed.xml` (RSS воды), `vk_posts_fields.json` (JSON воды), `gas_dp_home.html` (главная газовиков), `gas_dp_schedule_2026-11.docx` (график), `kml_water_map.kml` (карта отключений воды), `gas_dp_feed.xml` (пустая лента). Личных данных в них нет — это публичные сообщения служб.

## Сравнение вариантов

| Вариант | Надёжность | Простота | Бесплатные лимиты Cloudflare | Вывод |
|---|---|---|---|---|
| **Вода: JSON `wp-json` водоканала** | высокая: официальный сайт, поле дат и `modified` готовые | очень простая (`JSON.parse`, текст — одно поле) | 1 запрос в час, ≈ 35 КБ, почти нет вычислений | **основной** |
| Вода: RSS `/feed/` | та же | чуть сложнее (XML, 93 КБ) | 1 запрос, больше текста | запасной, если закроют `wp-json` |
| Вода: карта Google (KML) | сама карта обновляется водоканалом | сложная: нужны координаты дома, названий улиц в ней нет | 1 запрос | **не берём** (хозяину пришлось бы дать координаты; нет «улицы») |
| Вода: Telegram/Facebook | не нашёл Telegram; Facebook без входа не читается | — | — | недоступно |
| **Газ: график .docx с главной** | высокая по датам и адресам; раз в месяц | средняя: найти ссылку на главной + распаковать .docx (в Worker есть встроенный `DecompressionStream`) | главная (≈ 59 КБ) + файл (≈ 17 КБ, скачиваем только когда ссылка новая) = 2 запроса | **основной** |
| Газ: ленты/REST | RSS пуст, REST закрыт | — | — | нет |
| Газ: пересказ в «Наше місто» | зависит от сторонней редакции, вёрстка меняется | средняя | 1–2 запроса | только запасной, лучше не брать |
| Газ: сообщения об авариях на главной | всегда «после события» | простая (абзацы с датой) | в тех же 59 КБ | брать как «информационные», без «предупреждения» |

Лимиты Cloudflare (бесплатно): за один запуск cron итого **3 внешних запроса из 50** (вода 1 + газ 1–2); один раз в час это ничтожно. Одно ограничение, которое **надо проверить при реализации**: на бесплатном тарифе на запуск даётся мало процессорного времени (десятки миллисекунд). Поэтому: воду — через JSON (готовый разбор браузером-движком), главную страницу газа не разбирать целиком (искать ссылку через `indexOf`, а не регулярками по 265 КБ), .docx — только когда ссылка поменялась (хэш в `meta`).

## Рекомендация

1. **Вода (первой):** брать JSON водоканала раз в час. Совпадение по ключевым словам Ihor (район, улица). Неразобранное время — не показывать как факт, а давать выдержку текста с пометкой «время уточняйте в сообщении» и ссылкой.
2. **Газ (после воды):** брать месячный график `.docx` один раз при появлении новой ссылки и раскладывать по дням; напоминание «вечером накануне и за 2 часа» (времени суток в графике нет, поэтому «за 2 часа» — это «за 2 часа до 09:00 дня работ» как допущение, или только «накануне вечером» — решить с Ihor). Аварии по газу — информационно, «уже произошло, дом такой-то», только если совпадает со словами.
3. **«Коммуналка» в сводке:** свет (Yasno) + вода + газ одним блоком, если есть что сказать; нет отключений — молчать (решено).
4. **Не делать:** нет Telegram-разбора, нет карты Google, нет сторонних пересказов.

## Риски

- **Смена вёрстки.** Вода — через стандартный WordPress `wp-json`, он менее хрупок, чем HTML; газ — главная страница (HTML) и формат файла. Если разбор перестал находить записи 3 раза подряд — бот один раз говорит «источник не отвечает/поменялся» (решено).
- **Блокировки.** Один запрос в час, свой `User-Agent`; сомнение — только по газу (за Cloudflare) и по первому запросу из Worker. Если заблокируют — запасного канала нет.
- **Неполнота.** Вода: нет списка улиц (только районы + карта); газ: нет времени суток; срочные газовые аварии — только после события; случаи «воды нет из-за отключения света» (насосы) никто не объявляет. Бот этого не заменит — это надо сказать в подсказке настроек.
- **Ложные срабатывания.** Район длинный — совпадение по району шумнее, чем по улице; отсюда пометка «может коснуться».
- **Юридическое.** Отдельных условий использования не нашли; данные открытые и общедоступные; показываем краткую выдержку и ссылку, не копируем сайт.

## План реализации (3–5 шагов, тесты на сохранённых образцах)

Одна выкладка — по слову «выкладывай»; к шагам добавится страница в `LIVE-CHECKS.md`.

1. **Проверка из Cloudflare + образцы в тесты.** Пробный запрос к `wp-json` водоканала и к главной газа из Worker (без записи, через `wrangler dev --remote` или тестовый маршрут) — доходит ли, сколько CPU; в `test/fixtures/utilities/` положить сокращённые образцы (3–5 записей воды, фрагмент главной газа, `.docx`) — только публичный текст.
2. **Вода: `src/water.ts` + `test/water.test.ts`.** Разбор JSON → записи; фильтр «боржників»; тип (отключение / снижение давления / отмена); районы и ключевые слова; попытка разобрать время (3 формата), иначе «неподтверждённое»; ключ «уже сообщал» (`id` + `modified_gmt`). Тесты на образцах 23 сентября — 4 ноября 2026 (5 записей аварий и отмена).
3. **Газ: `src/gas.ts` + `test/gas.test.ts`.** Поиск ссылки на график на главной (`indexOf`, а не регулярки по всей странице), распаковка `.docx` (`DecompressionStream('deflate-raw')`, разбор zip по центральному каталогу, чтение `word/document.xml`), раскладка «дата → адреса», совпадение по словам; сообщения об авариях «после события» — отдельным типом. Тест на сохранённом ноябрьском файле (8 дат) и на урезанном/сломанном файле.
4. **Крон и сообщения.** Раз в час: запросы с общим тайм-аутом, ошибка источника → один раз «источник…» (не чаще раза в сутки); авария воды → сразу «почта» с упоминанием один раз; плановое → «накануне вечером» и «за 2 часа» (воде) / «накануне вечером» и «утром» (газу); «вернулось» — одним сообщением; блок «Коммуналка» в сводке. Настройки: слова места, включение воды/газа.
